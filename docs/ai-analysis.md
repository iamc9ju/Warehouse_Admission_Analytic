# AI Analysis

รายงาน v8 ใช้อัตรายืนยันต่อผู้มีสิทธิ์ (ผู้ยืนยัน ÷ ผู้มีสิทธิ์ × 100) เป็นอัตราหลักในเนื้อหา ตาราง และเกณฑ์สัญญาณ ไม่ส่ง rate ที่หารผู้สมัครให้โมเดล และปฏิเสธข้อความที่ระบุว่าอัตรายืนยันต่อผู้สมัคร เมื่อผู้มีสิทธิ์เป็นศูนย์ไม่มีฐานคำนวณและไม่ใช้เทียบอัตรา

หน้า `/ai-analysis` แทน chatbot เดิม ใช้ Gemini REST API ฝั่งเซิร์ฟเวอร์เท่านั้น

## Setup

- ใช้ `DATABASE_URL` ฐาน Neon เดิม และ `GEMINI_API_KEY` ใน environment ฝั่งเซิร์ฟเวอร์
- ตั้ง `GEMINI_MODEL` ได้ ค่าเริ่มต้น `gemini-3.1-flash-lite` ใช้ JSON mode และตรวจรูปแบบรายงานฝั่งเซิร์ฟเวอร์
- รัน `npm run ai:migrate` ครั้งแรกเพื่อเพิ่มสองตาราง (ไม่แก้ข้อมูลรับสมัคร)
- เปิดหน้า AI Analysis เลือกช่วงปีแล้วกดสร้าง ไม่เรียกโมเดลอัตโนมัติเมื่อเปิดหน้า

## Data and definitions

ข้อมูลสรุปดึงจาก fact/dim ด้วย CTE ใน SQL statement เดียวเพื่อให้ทุกระดับใช้ snapshot เดียวกัน
ส่งเฉพาะยอดรายปี/สาขา/รอบ/ประเภทหลักสูตรและนิยามให้โมเดล ไม่ส่ง student_key หรือ token
แยกคนไม่ซ้ำกับตัวเลือกสมัคร และไม่นำจำนวนคนข้ามกลุ่มมารวมกัน

ผู้มีสิทธิ์นับคนไม่ซ้ำที่มีอย่างน้อยหนึ่งแถวใน 8 สถานะตาม `report-types.ts` รวมสถานะไม่เข้าระบบมาดำเนินการใดๆ
นิยามนี้ตรวจเทียบกับ view ใน Neon ปัจจุบันแล้ว (SQL ต้นฉบับเก่าบางไฟล์มีเพียง 7 สถานะ)
อัตราต่อผู้สมัครและต่อผู้มีสิทธิ์แยกกัน ตัวหารศูนย์แสดงไม่มีฐานคำนวณ
ใช้เฉพาะปีที่เลือก ไม่มีการเพิ่มฐานเปรียบเทียบจากปีก่อนนอกช่วง เลือกปีเดียวเปรียบเทียบเฉพาะกลุ่มในปีนั้น เลือกหลายปีจึงเปรียบเทียบข้ามปีภายในช่วงได้

เกณฑ์สัญญาณเริ่มต้นอยู่ใน `RULES` และคำนวณด้วยโค้ด ไม่ใช่ให้โมเดลตั้งเกณฑ์เอง
เปรียบเทียบผู้สมัครอย่างน้อย 30 คนทั้งสองปี: ลด/เพิ่ม 10% หรืออัตราลด/เพิ่ม 3 จุดเปอร์เซ็นต์
ผู้สมัครสูงแต่อัตราต่ำใช้มัธยฐานจำนวนผู้สมัครรายสาขาและอัตราภาพรวมปีเดียวกัน
เกณฑ์นี้เป็นเกณฑ์เฝ้าติดตามเบื้องต้น ไม่ใช่นัยสำคัญทางสถิติ

## Status coverage

รายงานรุ่น v5 เพิ่มหัวข้อ “การใช้สิทธิ์และสถานะที่ควรติดตาม” แทนหัวข้อข้อจำกัดและข้อมูลที่ควรเก็บเพิ่ม
หัวข้อที่ถอดออกจะไม่แสดงในรายงานเก่าด้วย แต่ไม่ได้ลบประวัติในฐานข้อมูล
ทุก grain (ปี/รอบ/สาขา/ประเภทหลักสูตร) มีรายการสถานะจริงทั้งหมด พร้อมคนไม่ซ้ำต่อสถานะและตัวเลือกสมัคร
สละสิทธิ์รวมใช้ COUNT DISTINCT จากสละสิทธิ์และสละสิทธิ์ในรอบ 2 รวมกัน ไม่บวกจำนวนคนของสองสถานะ
rightsOutcomes ใช้หมวดและวิธีจัดกลุ่มเดียวกับ getRightsOutcomes เดิมใน rounds-repository.ts
กรณีมีมากกว่าหนึ่งหมวดแยกเป็น multiple; ผลรวมหมวดเท่ากับ eligible เสมอ
คนที่มีหลายสถานะแต่ยังเป็นหมวดเดียว เช่น สละสิทธิ์ทั้งสองสถานะ ยังคงอยู่หมวด resigned เพียงครั้งเดียว
จำนวน confirmed/resigned แบบมีอย่างน้อยหนึ่งแถวอาจต่างจากหมวด confirmed/resigned แบบไม่ซ้ำ ห้ามปนสองวิธี
หัวข้อสถานะต้องอ้างข้อมูลระดับปีครบทุกปีที่เลือกก่อนบันทึก และแสดงตารางจริงให้ตรวจได้โดยไม่พึ่งข้อความ AI
ไม่มีการเพิ่มตารางหรือ migration ใหม่: เก็บรายละเอียดเพิ่มใน input_snapshot JSONB เดิม

รุ่น v6: ตารางหลัก ตารางสถานะ และข้อมูลอ้างอิงใช้ confirmed/resigned แบบมีอย่างน้อยหนึ่งสถานะตรงกับ Dashboard ชุดเดียวกัน
นำคอลัมน์กลุ่มผ่านคัดเลือกอื่นและพบหลายหมวดออกจากการแสดงผล; rightsOutcomes เก่ายังเก็บใน snapshot เพื่อรักษาประวัติ แต่ไม่ส่งให้ Gemini และไม่ใช้แสดงยอดสถานะ
เพิ่มสละสิทธิ์ ไม่ใช้สิทธิ์ ยืนยันที่อื่น ไม่เข้าระบบ ไม่ผ่านคัดเลือก และผ่านในลำดับที่ดีกว่าในตารางหลัก
ฉบับเก่าที่ไม่มีข้อมูลแสดง — แทนการอนุมานเป็นศูนย์; ไม่มีการบวกยอดสละสิทธิ์สองสถานะซึ่งอาจซ้ำกัน
ตรวจรายงานสามปีที่บันทึกไว้เทียบยอด Dashboard โดยไม่เรียก Gemini ด้วย `node --env-file-if-exists=.env scripts/check-status-counts.mjs`

## Coverage by year (v7)

ทุกหัวข้อมี yearSummaries แยกครบทุกปีในช่วงที่เลือก มีข้อความและ evidenceIds ของปีนั้นจริง
ระบบกำหนด coveragePlan (หัวข้อ/ปี/หลักฐาน) จากข้อมูลก่อนเรียกโมเดล โมเดลส่งข้อความของแต่ละปี แล้วระบบผูกหลักฐานตาม slot ที่กำหนด ไม่เติมปีที่โมเดลข้ามและไม่แก้ข้อความเพื่อให้ผ่านการตรวจ
ปฏิเสธรายงานที่ขาดปี ปีซ้ำ ข้อความกล่าวถึงคนละปี หรืออ้างหลักฐานของปีอื่นแทน
หัวข้อภาพรวมและสถานะต้องอ้างภาพรวมปีนั้น หัวข้อรอบต้องอ้างทุกรอบที่มีข้อมูลในปีนั้น
หัวข้อสาขาต้องอ้างสัญญาณของปีนั้น ถ้าไม่มีต้องระบุว่าไม่พบตามเกณฑ์ ห้ามแทนด้วยสัญญาณปีล่าสุด
ข้อสรุปรวมของหัวข้อภาพรวม สถานะ และรอบต้องระบุปีต้นช่วงและปลายช่วง และมีหลักฐานรวมครบทุกปี ส่วนหัวข้อสาขาอาจเน้นสัญญาณบางปีในข้อสรุปรวม แต่ส่วนรายปีของทุกหัวข้อยังต้องมีครบทุกปี รวมปีที่ไม่พบสัญญาณ
หากเนื้อหาไม่ผ่านตัวตรวจ ระบบส่งเหตุผลให้โมเดลแก้ได้อีกหนึ่งครั้ง (สูงสุด 2 คำขอต่อการกดสร้าง ภายในเวลา 150 วินาทีรวม) ถ้ายังไม่ผ่านจะไม่บันทึก ไม่แก้ข้อความเองเพื่อหลบการตรวจ
เลือกปีเดียวใช้ปีนั้นเท่านั้นเหมือนเดิม รายงานเก่าไม่ถูกเขียนทับ แต่ขึ้นแจ้งว่ารูปแบบเก่าอาจยังครอบคลุมปีไม่ครบ
ทดสอบสร้างจริงทั้งช่วง: `node --env-file-if-exists=.env scripts/check-ai-live.mjs --generate --years 2567 2569`
ทดสอบจริงผ่าน: รายงาน v7 ทั้ง 7 หัวข้อมีปี 2567, 2568, 2569 ครบ (21 ส่วนรายปี) บันทึกและอ่านซ้ำได้โดยไม่เรียก Gemini ใช้เวลาประมาณ 25.8 วินาทีในรอบที่ผ่าน

## Persistence and generation

`admissions_dw.ai_analysis_reports` เก็บเนื้อหา structured JSON, input snapshot, fingerprint, ช่วงปี, โมเดล, prompt version และวันที่
ทุกครั้งที่ผู้ใช้กดสร้างใหม่บันทึกฉบับใหม่ เก็บประวัติเก่าไว้ หน้าแสดงรายการล่าสุด 30 ฉบับต่อช่วงปี
fingerprint มาจากข้อมูลสรุป นิยาม และเกณฑ์ของช่วงปีที่เลือก การ reload ข้อมูลเดิมไม่ทำให้ stale
ตรวจความเปลี่ยนแปลงเมื่อเปิดหน้า กลับเข้าแท็บ หรือกดตรวจข้อมูลล่าสุด ไม่เรียก AI เอง

`ai_analysis_jobs` เป็น lease ข้าม process ต่อช่วงปี ป้องกันคำขอพร้อมกัน มีอายุ 4 นาที
Gemini timeout 150 วินาที; ตรวจ schema, 7 หัวข้อ, STOP และ evidence IDs ก่อนบันทึก
รายงานที่สร้างล้มเหลวไม่ทับฉบับเก่า ไม่มีคำตอบสำรองปลอมว่าเป็น Gemini
การบันทึกและปล่อย lease สำเร็จใน SQL เดียว ผู้ถือ lease เก่าไม่สามารถเขียนทับงานใหม่ได้
ระหว่างเปลี่ยนหน้า งานที่เซิร์ฟเวอร์ยังทำต่อจะบันทึกผล และหน้า poll สถานะทุก 5 วินาทีเมื่อกลับมา
หาก host ยุติ process ก่อนสำเร็จ lease จะหมดอายุและสร้างใหม่ได้ ยังไม่มี background queue สำหรับรับประกันงานหลัง process shutdown

## Validation

```sh
npm run ai:test
npm run typecheck
npm run build
node --env-file-if-exists=.env scripts/check-ai-live.mjs --generate
```

คำสั่งสุดท้ายเรียก Gemini จริงหนึ่งครั้งและส่งข้อมูลสรุปให้ผู้ให้บริการ จากนั้นตรวจผลบันทึกและยอดรายปีกับ dashboard
รันโดยไม่ใส่ `--generate` เพื่อตรวจอ่านฉบับเดิมโดยไม่เรียกโมเดล
การตรวจ schema และแหล่งอ้างอิงไม่รับประกันความถูกต้องของคำอธิบายทุกประโยค ผู้ใช้ยังต้องตรวจทานก่อนนำไปใช้

## Executive overview (prompt v9)

หัวข้อแรกสังเคราะห์ภาพรวม 3–5 ประเด็นจากแนวโน้มการสมัคร การใช้สิทธิ์ สาขา และรอบ TCAS โดยไม่แสดงกล่องรายปี แต่หลักฐานแต่ละมิติต้องครอบคลุมทุกปีที่เลือก หัวข้อ 2–7 ยังคงสรุปแยกรายปีครบตามช่วงที่เลือก ใช้นิยามการนับเดิมและอัตรายืนยันต่อผู้มีสิทธิ์ รายงานเดิมยังอ่านได้ แต่ต้องสร้างฉบับใหม่เพื่อรับเนื้อหาตาม prompt นี้
